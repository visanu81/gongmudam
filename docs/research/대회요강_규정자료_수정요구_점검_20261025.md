# 대회요강의 규정 자료 수정 요구와 현재 구현 점검

점검일: 2026-10-25  
범위: 세션 2 지정과제(서무비서·규정 제·개정 에이전트), 서비스의 자료 등록·수정 흐름. PDF는 pypdf 6.21.1로 전체 19쪽 텍스트 추출 후 페이지를 대조했다.

## 요약

요강에는 **기관별 서무 규정·서식 자료를 사용자가 추가·수정·삭제할 수 있도록 설계**하라는 문구가 있다. 현재 Gongmudam에서는 기관 사용자가 새 자료를 등록하고, 답변 근거에서 켜고 끄며, 원문 파일 자체를 고친 뒤 재분석·재등록해 최신 버전으로 바꾸는 흐름이 가능하다. 그러나 기존 등록을 직접 편집하거나 삭제하는 UI/API는 확인되지 않았다. 공식 법령·공통 근거 자료팩은 고정된 해시 검증 자산이며 사용자 편집 대상이 아니다.

또한 문구상으로 이는 **서무비서 과제 카드의 기본기능**이고, 요강 p.11은 기본기능이 의무가 아니며 일부 또는 추가 구현 모두 팀 재량이라고 명시한다. 규정 제·개정 에이전트 카드(p.10)도 기본기능/선택기능으로 나뉘며 팀 재량이다. 별도로 대회 안내·일정은 변경될 수 있지만 재안내한다는 일반 조항이 있다.

## 요강 근거

- 안내서 본문 p.4: “행사 관련 사항은 변경될 수 있으며 변경시 재안내 예정.” 첨부1 p.14: “대회 세부 안내 사항은 변경될 수 있으며, 변경 시 재안내함.” 즉 변경 가능성은 규정의 참가자 편집 권한이 아니라 주최 측의 공지 변경 조항이다.
- 첨부1 p.9, 세션2 과제 ② 서무비서 기본기능: “기관의 규정·서식을 수정·삭제·추가할 수 있는 구조.” 같은 쪽 선택기능 예시는 공통/기관/개인 자료 층 분리와 각자 등록, 처리 이력 관리 등이다.
- 첨부1 p.11: 과제 카드 “기본 기능”은 심사 공통 확인 항목이나 의무가 아니며 “팀 재량에 따라 일부만 구현하거나 그 이상을 구현”할 수 있다고 명시.
- 첨부1 p.10, 과제 ③ 규정 제·개정 에이전트: 개정 의도 입력으로 조문 수정안과 신구조문대비표를 만드는 기능이 기본기능 예시다. 선택기능으로 절차별 지원, 상위법 개정 영향 탐색, 유사 규정 비교 및 인용 오류 점검 등이 있다.
- 첨부1 p.12: 제출 산출물은 마감 후 GitLab에서 수정·업데이트할 수 없고, 변경 이력이 있는 과제는 심사에서 제외될 수 있다. p.13은 수상작에 대해 행안부가 복제·수정·배포·2차적 저작물 작성 등의 무상 사용권을 부여받는다고 한다.
- 첨부1 p.13의 2종 이상 모델 구동은 “권장”이지 의무가 아니다.

## 현재 서비스 동작과 경계

1. **기관 자료 추가**: 자료함에서 파일을 연결·읽은 뒤 답변 근거로 등록한다. `/api/knowledge/libraries/{key}/sources`가 종류(법령·규정/기관 지침/업무편람/참고자료), 기관, 시행일을 받고 저장한다. 같은 자료함·파일 재등록은 기존 항목을 갱신하고 활성화한다. 근거 목록에서 활성/비활성 전환이 가능하다. UI: `service/static/folder-knowledge.js`, API/검증: `service/app/knowledge.py`.
2. **내용 수정/교체**: 등록된 원문을 직접 편집하는 엔드포인트는 없다. 원본 자료를 사용자가 고친 뒤 폴더를 다시 분석하고, 다시 등록하면 해시가 달라진 새 파일 내용으로 근거를 갱신하는 방식이다. 등록 원문과 현재 파일의 SHA-256이 다르면 `current=false`로 표시되고, 최신본 재분석 후 등록하도록 안내/차단한다(`knowledge.py`, `folders.py`). 파일 추가·분류·업무 묶음 등 자료함 편집 이력은 별도 기록된다.
3. **삭제**: 등록 근거의 비활성화는 되지만 등록 항목을 완전히 삭제하는 API/UI는 확인되지 않았다. 원문 파일 삭제 기능과 근거 레코드 삭제는 동일하지 않다. 사용자 관점에서 “규정 삭제” 요구를 완전히 충족한다고 말하긴 어렵다.
4. **공식 공통 규정 자료**: `official_sources.py`가 로컬 manifest 및 원문/발췌 해시를 확인해 메타데이터를 붙인다. `office_knowledge.py`와 `finance_knowledge.py`도 고정된 `reference_data` 팩의 파일 해시와 허용 도메인을 검증한다. 이는 승인된 번들 업데이트로 바꾸는 큐레이션 구조이고, 기관 사용자가 화면에서 법령/공통 자료팩을 수정하는 구조가 아니다.
5. **자동 감지**: 폴더 감지는 파일 변경을 찾아 로컬 AI 제안을 만들고 원문은 변경하지 않는다고 설명한다. 확인한 API에는 설정·재시도·제안 보류 등이 있지만 규정 내용을 자동 확정/개정하는 흐름은 없다. 변경 제안은 담당자 검토·적용 경로다.

## 판단 및 다음 개선

**부분 충족**: 기관별 참고자료를 추가하고 최신 원문으로 교체하는 것은 가능하지만, 등록 자료의 직접 메타데이터 편집과 완전 삭제가 없으므로 요강의 수정·삭제·추가를 사용자 기능으로 완결했다고 보기 어렵다. 공통 법령 팩이 편집 불가능한 점은 안전한 운영 경계로 보이며, 이를 기관 자료 관리와 혼동하지 않도록 UI에 “기관 자료만 직접 관리 가능 / 공통 법령은 검증된 업데이트로 반영”을 명확히 쓰는 게 좋다.

다음 구현은 기관 자료에 한정해 **등록 항목 메타데이터 편집 및 삭제(확인·감사 이력 포함)**를 더하는 것으로 좁히는 것을 권한다. 원문 변경은 현재의 재분석·해시 확인·재등록 절차를 유지하고, 사용자가 편집 가능한 범위가 원문 문구를 서버에서 덮어쓰는 것인지 자료 메타데이터/참조 연결인지 구분해 보여야 한다. 규정 본문 수정은 원본 보존 원칙과 맞지 않으므로 원본 파일 교체 방식이 적절하다.

## 확인한 코드 위치

- `service/app/knowledge.py`: 자료 등록, SHA-256 현재성 확인, 활성화/비활성화 API
- `service/app/folders.py`: 폴더 재분석과 파일 분류 API
- `service/static/folder-knowledge.js`: 근거 등록 및 사용 여부 UI
- `service/app/official_sources.py`, `office_knowledge.py`, `finance_knowledge.py`: 해시 검증된 공통/공식 근거
- `service/app/folder_watch.py`: 변경 감지 설정·제안 보류 등
