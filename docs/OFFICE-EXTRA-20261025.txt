# 보충 서무 근거 묶음 현황

점검일: 2026-10-25  
범위: 검증된 서무 공통 근거에 개인정보 권리, 기록물 세부 절차, 정보공개 수수료·반복 청구 근거를 추가한 `office-extra-20261025` 묶음.

## 변경 요약

- 원래 서무 묶음은 조문 24개와 검토 답변 규칙 19개를 유지한다. 새 보충 묶음은 별도 컬렉션과 라이브러리로 등록되며 기존 원문이나 등록자료를 교체하지 않는다.
- 보충 묶음은 검토된 전체 조문 12개와 새 답변 규칙 11개를 포함한다. 전체 등록 자료는 86개(기존 74개에서 12개 추가), 이 중 서무 공통·보충팩의 AI 비사용 답변 규칙은 30개(기존 19개에 11개 추가)다. 등록 자료에는 기존 여비·복무·예산 근거와 매뉴얼도 포함되므로 법령 원본 문서 86종이라는 뜻은 아니다.
- 별도 묶음의 추가 조문은 개인정보 보호법 제22조의2·제26조·제35조·제36조·제37조, 공공기록물 관리에 관한 법률 시행령 제18조·제20조·제26조·제43조, 정보공개법 제11조의2·제17조와 시행령 제17조다.
- 자료 원문·발췌 해시와 시행일을 확인한 뒤 답한다. 누락·변경·비활성 원문, 자료에 없는 세부 기한, 과태료, 오래된 적용 시점 등은 근거를 제시하지 않고 답변을 보류한다.

## 실제 질문 점검

실행 점검은 총 41개 질문을 다뤘다. 이 중 30개는 기존·보충 규칙의 대표 질문, 4개는 표현을 바꾼 질문, 7개는 자료 부족·범위 밖·시점 문제로 답변을 보류해야 하는 질문이다. 대표 질문은 원문 출처와 인용을 제시하고 `ai_used=false`인 것을 확인했다. 표현 변형도 같은 주제의 검토 규칙과 자료를 사용했다.

실제 로컬 AI 연결에서 `ConnectTimeout`이 발생한 경우에도 검색 답변과 요약 트리가 AI 비사용 시와 같았고, 안내 문구는 “로컬 AI 응답을 확인하지 못해 검색 원문을 표시합니다.”였다. AI 연결 여부가 검토 답변의 근거를 바꾸지 않는다.

라이브 검증에서 기존 비공개 사용자 자료도 보존됐다: 업무 프로젝트 5개, 파일 12개, 대화 46개. 설정과 그 밖의 데이터베이스 행도 유지됐다. 등록 결과의 `business_rows_preserved`가 참이며 보충 원문 12건은 `office-extra-20261025`에만 추가됐다.

## 54개 대표 업무의 근거 범위

업무 대표 질문 54개를 점검했다. 21개는 현재 자료로 답할 수 있고, 27개는 기관별 절차·서식·일정·담당자 자료가 더 필요하다. 이 판정은 업무 전체의 기능 완성도를 뜻하지 않으며, 각 업무에서 대표 질문 하나를 확인한 결과다.

질문에 직접 맞는 공통 출처가 부족한 6개 항목:

| ID | 업무 | 확인 질문 |
| --- | --- | --- |
| D01 | 공문 접수·배부 | 공문을 접수한 뒤 담당 부서로 배부하는 절차는? |
| D02 | 공문 기안·회신 지원 | 공문 기안에서 검토와 결재는 어떤 순서로 하나요? |
| B07 | 출장 결과보고 | 출장 결과보고서인 출장복명서는 언제까지 제출하나요? |
| P05 | 비품·자산 관리대장 | 공공기관 비품 자산 관리대장에 반드시 기록할 항목은? |
| P07 | 재물조사 지원 | 공공기관 재물조사의 법정 실시 주기는? |
| P09 | 불용·폐기·반납 지원 | 지방자치단체 불용 물품 폐기와 처분 절차는? |

기관 내부 자료를 추가하면 확인할 수 있는 질문과, 공통 근거 자체가 아직 부족한 질문을 구분해야 한다. 54개 대표 질문을 전체 업무의 포괄적 법률 검토로 해석하지 않는다.

## 등록 및 데이터 보존

검증 데이터베이스에서 보충 묶음 12건의 미리보기와 실제 추가를 확인했다. 재등록은 이미 있는 동일 원문을 건너뛰어 중복 추가하지 않는다. 별도 백업을 생성했고 기존 업무 행과 원래 `office-20261025` 라이브러리가 보존됐다. 적용은 이미 완료됐으므로 아래 `--apply` 명령을 다시 실행하지 않는다.

기존 데이터베이스에 대한 등록 명령은 다음과 같다. 기본 명령은 읽기 전용 미리보기이며 실제 쓰기는 `--apply`를 명시할 때만 수행한다.

```powershell
Set-Location service
.venv\Scripts\python.exe -m tools.register_office_extra_pack --db data\folders.db
# 새 적용 환경에서 실제 등록할 때만 아래 옵션을 덧붙인다.
.venv\Scripts\python.exe -m tools.register_office_extra_pack --db data\folders.db --apply
```

검증 당시 로컬 서비스 주소는 `http://127.0.0.1:8787`이었다.

## 편집과 최신성의 경계

대회 안내서 첨부1 p.9는 서무비서 기본기능 예시로 기관 규정·서식의 수정·삭제·추가가 가능한 구조를 든다. 그러나 p.11은 과제 카드의 기본기능이 의무가 아니며 팀이 일부만 구현하거나 더 구현할 수 있다고 명시한다. 따라서 이번 결과를 그 기능 전체가 완성됐다는 의미로 표현하지 않는다.

현재 사용자는 기관 자료를 추가하고, 원본 파일을 수정한 뒤 다시 분석·등록해 바뀐 원문을 반영할 수 있다. 근거를 사용하지 않도록 끄는 기능도 있다. 등록자료를 화면에서 직접 편집하거나 완전히 삭제하는 기능은 이번 구현에 추가하지 않았다. 공식 법령 자료는 기관 자료와 달리 해시 검증되는 배포 묶음이며, 기관 사용자가 원문을 직접 바꿀 수 없다. 법령 변경을 감지해 검토된 답변의 SHA를 자동 승인하는 기능도 없다.

다음 편집 기능을 설계할 때에는 원본 파일을 보존하고 버전별로 교체하는 방식을 고려한다. 검토가 필요한 자료를 삭제하기보다 먼저 비활성화해 답변 근거에서 제외하는 것이 현재 가능한 조치다. 규정 변경을 자동으로 답변 근거에 반영하지 않는다. 출장 법령 모니터링도 일부 항목에 한정된다.

## 테스트와 재현 근거

- `service-tests.txt`에는 마지막 표현 변형 수정 전 전체 서비스 테스트 870건 통과 결과가 기록돼 있다. 이를 871건 통과로 주장하지 않는다.
- 그 뒤 표현 분기 수정 관련 18개 테스트가 통과했고, 기존 기관 자료 등록·사용 제외 검사를 포함한 최종 관련 검사 34개도 통과했다. 루트 레벨 33개 검사도 통과했다. 전체 870건 재실행 결과로 혼동하지 않는다.
- Graphify는 기존 코드 지도에서 소스 194개를 대상으로 전체 갱신됐다. 갱신 후 변경·추가·삭제 소스 차이는 0개, 그래프 파일과 복사본이 일치하고, 모델 토큰 사용량은 0이었다.

검증 증거는 `docs/evidence/office-extra-20261025/`에 보관한다. 주요 파일은 `live-validation.json`, `coverage-54.json`, `registration.json`, `graphify-status.json`, `service-tests.txt`다. 대회 요강 검토 근거는 `docs/research/대회요강_규정자료_수정요구_점검_20261025.md`다.

기존 v76 제출 ZIP과 submission-data는 이번에 갱신하지 않았다. 다음 패키지에는 재무·서무 공통팩 및 이번 보충팩의 코드·원문·발췌·질문 규칙을 포함하고, 86개 등록 자료를 내보내 실제 새 환경에서 복원되는지 검증해야 한다.
