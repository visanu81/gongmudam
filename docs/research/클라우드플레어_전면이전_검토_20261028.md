# 공무담 Cloudflare 전면 이전 검토

검토일: 2026-10-28  
범위: 현재 PC 서버(FastAPI)를 Cloudflare만으로 운영할 수 있는지, 기본 AI를 Upstage로 두고 다른 모델로 바꿔 끼우는 구조가 대회요강과 맞는지.  
근거: 대회요강 추출본(`대회참여/.../work/competition-scope-20261024/official-guide.txt`), `service/app` 코드, Cloudflare 공식 문서(2026-10-28 조회).

## 결론

가능하다. 단, 코드를 그대로 올리는 것이 아니라 **저장·파일·백그라운드 부분을 Cloudflare 방식으로 바꾸는 이식 작업**이 필요하다. 답변 로직(검색·규칙·여비 계산·답변 구성)은 순수 Python이라 그대로 살릴 수 있다. AI는 이미 공급자 교체 구조(`llm.py`)라 Upstage 기본 + Workers AI 보조 모델로 요강의 "모델 비종속·2종 이상 구동" 권장을 클라우드 안에서 충족할 수 있다. Workers 유료 플랜(월 5달러)이 사실상 필수인데, 계정에 이미 Workers Paid가 구독되어 있다(2026-10-28 대시보드 확인, 11-24 갱신). 같은 계정의 Zero Trust 무료 플랜(Teams Free Base)으로 Cloudflare Access 로그인을 붙일 수 있다.

## 대회요강에서 관련된 조건 (세션2)

- 결과물 형태 자유(웹 가능). GitLab README에 **접속 주소**·실행 방법을 쓰게 되어 있어 상시 접속 주소는 심사에 유리하다.
- 심사위원이 구동안내서대로 구동할 수 없으면 제외될 수 있다 → PC가 꺼지면 죽는 지금 구조(터널)는 위험 요소.
- 모델 비종속 구조 권장, **2종 이상 모델에서 주요 기능 구동 입증 권장**. 공통기반 지원 모델 예: Gemma, GPT-OSS, EXAONE, HyperCLOVA X, Solar.
- 심사 지표 "확산용이성 30점": 특정 LLM 비종속, 타 기관 이식·정보화사업 이관 용이성.
- 지정과제 기본기능: 한글·PDF·엑셀 자료를 **폴더째 넣어도 작동**, 출처 확인, 검토·수정.
- 마감 11.11, 마감 후 GitLab 수정 불가.

## Cloudflare 제약 (공식 문서)

| 항목 | 내용 |
| --- | --- |
| Python Workers | FastAPI 지원. 순수 Python 패키지와 Pyodide 내장 패키지 사용 가능. C 확장 패키지는 WebAssembly 빌드가 있어야 함 |
| 메모리 | 요청 처리 단위당 128MB (무료·유료 동일) |
| CPU 시간 | 무료 10ms(Python 앱엔 사실상 불가) / 유료 기본 30초, 최대 5분 |
| 배포 크기 | 압축 해제 기준 64MiB |
| D1(SQLite) | 유료 DB당 10GB, 호출당 쿼리 1,000개, 행 최대 2MB. 접근은 비동기 바인딩 |
| R2 | 원문 PDF·업로드 파일 저장 |
| Containers | 유료 플랜. Docker로 기존 서버를 거의 그대로 실행 가능하나 디스크가 영속 저장소가 아니어서 DB는 결국 D1/R2로 옮겨야 함 |
| Workers AI | `gemma-4-26b-a4b-it`, `gpt-oss-120b`, `gpt-oss-20b`, `qwen3-30b-a3b-fp8`, Llama 등. EXAONE·Solar는 목록에 없음 |

## 현재 코드의 PC 의존 부분과 대응

| 기능 | 현재 구현 | Cloudflare 대응 | 난이도 |
| --- | --- | --- | --- |
| 화면 | 이미 Workers 정적 자산 | 그대로 | - |
| 공개 지식 검색·답변(복무·여비·사무·회계·물품) | 순수 Python 순위 계산, 텍스트 약 3.4MB | Python Worker에 번들 또는 R2에서 로드 | 낮음 |
| 원문 PDF 등 원본 69MB | 로컬 파일 | R2 | 낮음 |
| AI 호출 | `llm.py` 공급자 추상화, httpx | Upstage 기본, Workers AI를 두 번째 공급자로 추가. Ollama는 자체 설치용 옵션으로 유지 | 낮음 |
| 업무 DB(자료함·프로젝트·일정·기관규정·답변검토·여비 등 9개 모듈) | `sqlite3` 동기 호출 | D1. SQL은 대부분 재사용, 호출부를 비동기로 바꾸는 어댑터 필요 | **높음** |
| 파일 읽기(PDF·엑셀·한글·워드) | pypdf, openpyxl, olefile, python-docx | 업로드 후 Worker에서 파싱. 앞의 셋은 순수 Python, python-docx는 lxml 필요(Pyodide 지원 여부 실측 필요). 대용량 파일은 128MB 메모리 주의 | 중간 |
| 폴더째 넣기·폴더 감시·파일 선택창 | `os.walk`, 스레드 감시, tkinter, subprocess | 브라우저 폴더 업로드(`webkitdirectory`)로 대체. 상시 감시는 "다시 올리기"로 대체 | 중간 |
| 백그라운드 작업(폴더 AI 분석, 규정 변경 감시, 모델 상태) | 스레드 | Queues·Cron Triggers | 중간 |
| 사용자 구분 | 1인 PC 전제 | 로그인과 사용자별 데이터 분리 필요(Cloudflare Access 등) | 중간 |

규모: `service/app` Python 약 14,900줄, API 경로 약 200개.

## 이식 방식 비교

1. **Python Workers + D1/R2 (권장)**: 답변 로직 재사용, 서버 없음, 상시 접속. DB 호출 비동기화가 가장 큰 작업.
2. **Containers**: 단기간에 올리기는 쉽지만 저장소 문제는 그대로 남고, 유휴 후 첫 요청이 느리며 비용 구조가 복잡하다. 과도기용.
3. TypeScript 재작성: 가장 깔끔하지만 기간상 비현실적.

## AI 교체 구조 제안

- 기본: Upstage `solar-pro4` (API 키는 Workers Secret).
- 클라우드 보조: Workers AI `gemma-4-26b-a4b-it` 또는 `gpt-oss-120b` — 요강이 예로 든 Gemma·GPT-OSS와 같은 계열이라 "2종 이상 구동 입증"을 클라우드에서 바로 할 수 있다. 한국어 품질은 실측 필요.
- 자체 설치: Ollama(로컬 Gemma 등)는 설정으로 선택하는 옵션으로 유지 → 폐쇄망 기관 이관 설명에 활용.
- AI 끔(원문 검색만) 경로는 그대로 필수 검증 대상.

## 주의할 점

- AGENTS.md 원칙상 공유 사이트에는 공개 자료·합성 사례만 둔다. 개인 업무자료까지 클라우드로 올리면 이 원칙과 개인정보 경계가 바뀌므로, 로그인·사용자 분리를 먼저 갖추거나 개인용은 PC 설치본으로 남기는 결정이 필요하다.
- 마감(11.11)까지 약 2주. 전체 이식을 한 번에 하기보다 단계로 나누는 것이 안전하다.

## 단계안

1. **실측(반나절)**: 최소 Python Worker에 `knowledge.retrieve`·답변 구성을 올려 실제 질문 1개로 메모리·CPU·콜드스타트·패키지 호환(pypdf, openpyxl, olefile, python-docx) 측정.
2. **공개 답변 경로 이전**: 지식 질의·여비 계산·Upstage/Workers AI 전환을 Workers로. 터널 없이 공유 사이트 동작, 로컬 앱과 동일 질문 비교(`check_answer_parity`).
3. **업로드·자료함·프로젝트**: D1/R2 어댑터, 브라우저 폴더 업로드.
4. **기관 규정·답변 검토·일정**, 백그라운드 작업 이전, 로그인.

## 1단계 실측 결과 (2026-10-28)

방법: `service/app`을 거의 수정하지 않고 별도 Worker `gongmudam-spike`(workers.dev)에 배포. 공개 자료·합성 예제만 포함, 기존 공유 사이트와 별개. 실험 코드는 `work/cf-spike/`(git 제외).

| 항목 | 결과 |
| --- | --- |
| 패키지 | fastapi, pydantic, httpx, python-multipart, pypdf, openpyxl, olefile, python-docx, lxml, sqlite3 모두 불러오기 성공 → **PDF·엑셀·한글·워드 읽기 가능** |
| 번들 크기 | 원본 PDF 포함 65.6MB로 한도 초과. PDF 제외 37MB(gzip 11MB)로 배포 성공 → 원본은 R2 필수 |
| 파일 쓰기 | 번들 폴더는 읽기 전용. `/tmp`(메모리, isolate마다 사라짐)만 쓰기 가능 → 영속 데이터는 D1/R2 필수 |
| 스레드 | 불가. FastAPI가 일반 `def` 엔드포인트를 스레드로 실행하므로 그대로면 전부 500 오류. 즉시 실행으로 우회하면 동작 |
| 시작 시 난수 | `model_status.py`의 `secrets.token_bytes`가 시작 시점 실행이라 스냅샷 거부 → 지연 생성으로 수정 필요 |
| **앱 전체 시작 시 로드** | **"Python startup exceeded memory limits"로 배포 거부(128MB 초과)** |
| 앱 전체 요청 시 로드 | 동작은 하나 새 isolate마다 12~23초, 같은 isolate 재사용 시 0.5초. 방문이 적으면 대부분 느린 쪽 |
| **답변 경로만 분리** | 지식·안내·근거 모듈 10개만 스냅샷 → 배포 성공(시작 3.5~7.5초), 질의 **0.3~2.9초** |
| 근거 검색 결과 | 빈 DB라 근거 0건. 공개 자료 123건 등록 단계를 D1로 옮겨야 PC와 같은 답 비교 가능(미검증) |

판단: **앱을 Worker 하나에 통째로 올리는 방식은 메모리·속도 때문에 불가.** 기능 묶음별로 Worker를 나누면(답변 / 자료함·프로젝트 / 여비 / 일정·기관규정) 각각은 한도 안에서 빠르게 돈다. 이식 단위는 "Worker 분할 + D1/R2 + 스레드 제거"로 잡는다.

## 확인하지 못한 것

- D1의 FTS5 지원 여부(현재 코드는 FTS 미사용이라 필수는 아님).
- 공개 자료 등록 후 PC 앱과 같은 근거·답변이 나오는지(빈 DB로만 시험).
- Upstage·Workers AI 호출(이번 실측은 AI 끔 경로만).
- Workers AI 모델의 한국어 답변 품질과 요금(2차 출처끼리 가격이 달라 공식 요금표 확인 필요).
- Containers의 정식 출시 여부와 인스턴스 사양.
