공무담 v76 · 검증 안내

검증 범위와 상태
v76의 주요 변경은 프로젝트 자료에서 AI 없이 핵심 요약, 일정·할 일 정리, 선택 자료 비교, 보고서 초안을 제공하는 기능입니다. 기능 시나리오는 합성 교육 자료로 수행했습니다. 아래 소스 검사 결과와 새 설치 검증은 서로 다른 단계입니다.

소스 단계 결과
- 프로젝트 기능 시나리오 검사 56개, 폴더 회귀 검사 67개, 통합·패키지 검사 33개가 통과했습니다(총 156개).
- API 시나리오에서 기본 모드가 offline이고, 교육 자료 범위, 날짜·할 일 발췌, 두 파일 비교, 초안 템플릿, 미확인 내용 보류, 인용 단위 일치, 원본 불변을 확인했습니다. GUI 시나리오에서도 요약·일정·비교·초안 흐름을 확인했습니다.
- 근거의 최대 범위는 24단위·24,000글자입니다. 답변은 검색된 원문 발췌이며 모든 파일·문장을 포함한다고 보장하지 않습니다.
- 증거: `docs/evidence/v76/tasks-api.json`, `docs/evidence/v76/tasks-gui.json` 및 관련 `*-screen.jpg`. `baseline-initial.json`은 수정 전 실패 재현으로 배포 검증 증거가 아닙니다.

새 ZIP 설치 및 설치본 확인
- 같은 Windows 개발 PC에서 새 한글·공백 경로에 v76 ZIP을 풀고 새 가상환경으로 설치했습니다. `install.bat`의 `pip --no-index`가 포함 wheel만 사용했고 `pip check`도 통과했습니다. 설치 시간은 29.641초였습니다.
- 설치본에서 `run.bat --port 8896 --no-browser`로 실행해 개인용 v76 화면과 offline 기본 모드를 확인했습니다.
- 설치된 서비스 테스트 831개가 통과했습니다(테스트 실행기 171.293초, 래퍼 기준 175.359초). 별도 설치본 검사도 루트 Python 19개, 루트 Node 31개, 서비스 Node 25개가 통과했습니다. 합계 906개이며, 앞서 기록한 소스 단계 156개와 별도 집계입니다.
- 설치본 API에서 요약·일정·비교·초안·미확인 질문·미회신 부서 질문을 확인했습니다. 인용 48개 원문 단위가 모두 일치했고, 다운로드한 원본 4개 해시 및 원본 파일 내용도 변하지 않았습니다.
- GUI에서 네 가지 질문 흐름을 확인했습니다. 비교 답변의 8행 근거를 대조했고, 초안 수정 후 다시 열어도 저장 내용이 유지됐습니다.
- 긴 문서 검사에서 PDF 25쪽과 XLSX 여섯 번째 시트 C501의 자료를 찾았습니다.
- 같은 개발 PC의 새 설치만 확인했으며, 다른 물리 PC에서는 검증하지 않았습니다.
- 서버를 재시작한 뒤에도 대화 20건, 자료 4건, 수정한 초안과 설정 해시가 유지됐고 대기 중인 읽기 작업이 없었습니다. 화면을 다시 열어서도 초안 수정 내용이 보존됐습니다.

교육 예제에서 확인할 기대 동작
자료는 `service/sample_data/projects-v76/교육 자료/{교육 최초 안내.txt,교육 변경 안내.txt,교육 회신 현황.txt}` 및 `service/sample_data/projects-v76/개별 추가/물품 납품.txt`입니다. 안내 두 건에는 11월 6일 18:00과 11월 9일 17:00 마감, 3층 교육실과 5층 회의실이 각각 기재되어 있습니다. 변경 안내의 최종 승인·적용은 자료만으로 확정하지 않습니다.

재현 질문:
- `교육 자료 핵심만 간단히 정리해줘` — 교육 업무, 상충하는 날짜·장소, 진행 상황과 할 일을 근거와 함께 발췌하고 확인 필요를 표시합니다.
- `교육 날짜와 회신 마감, 내가 해야 할 일을 정리해줘` — 두 마감과 교육일, 자료에 적힌 할 일을 모두 보여주며 한 날짜로 임의 통합하지 않습니다.
- `두 자료의 마감과 장소 차이를 비교해줘` — 교육 최초 안내와 교육 변경 안내 두 파일을 선택해야 합니다. 문서별 값을 비교하고 적용 문서는 담당자 확인으로 남깁니다.
- `교육 자료 요약 보고서 초안을 써주세요` — 근거가 연결된 정형 초안을 만들고, 알 수 없는 목적·최종 적용안·승인·발송 여부는 `[작성 필요]`로 둡니다.

자료에 없는 사실을 질문해 보류 동작을 확인할 때에는 `항공권 환불 규정을 요약해줘`라고 질문합니다. 답을 지어내지 않는지, 인용이 해당 원문 행과 일치하는지 확인합니다. 원본 자료의 해시나 내용이 바뀌지 않는지 확인합니다.

등록 자료와 모델 관련 범위
36개 공식 원문 자산의 기존 구성은 법령·지침 30건과 매뉴얼 PDF 6개(총 221쪽)입니다. 이는 보존된 이전 스냅샷이며 v76 검증으로 최신성이 확인되거나 갱신된 것이 아닙니다. 최신 법령·지침을 보장하는 근거로 사용하지 마세요.

해당 원문 36개(그중 매뉴얼 PDF 6개·221쪽)는 보존 스냅샷과 해시가 일치했습니다. 이는 자산 보존 확인이며 법령·지침의 최신성 검증은 아닙니다.

v76 기능 확인은 실제 로컬 모델 응답 시험이 아닙니다. 로컬 AI는 선택 사항이고 가중치는 패키지에 포함되지 않습니다. v74의 두 모델 결과도 과거 버전 기록이며 v76 결과로 인용하지 않습니다.

설치본 증거
설치 요약은 `docs/evidence/v76/fresh-validation.json`, 프로젝트 API는 `fresh-project-tasks.json`, GUI는 `fresh-gui.json`과 `fresh-compare-evidence.jpg 및 fresh-compare-result.jpg`, PDF·XLSX 확인은 `fresh-long-documents.json`, 원문 자산 해시는 `fresh-knowledge.json`, 서버 재시작 보존은 `fresh-restart.json`에 있습니다. 테스트 출력은 `service-tests.txt`, `root-python-tests.txt`, `root-node-tests.txt`, `service-node-tests.txt`입니다.

설치본 테스트에는 모형 서버의 오류 응답을 의도적으로 확인하는 사례가 포함됩니다. 로그의 LLM 오류 문구는 해당 실패 처리 검사이며, 실제 로컬 모델을 구동한 기록은 아닙니다. 최종 ZIP은 검증한 설치 후보와 실행 코드·자료 해시를 대조하며, 완료된 안내서와 검증 증거만 추가·갱신합니다.
