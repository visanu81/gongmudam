공무담 v77 · 새 설치 검증 결과
확인일: 2026-10-26

구현 범위
기관 규정·서식의 초안 저장, 새 버전 작성, 변경 비교, 명시적 답변 적용,
적용 해제, 복원 가능한 삭제, 이전 원문과 이력 보존을 포함한다.
AI 없이도 적용한 버전의 본문을 검색·발췌하며 기관 자료는 공통 법령과 구분한다.
기관명과 등록 연결어를 질문에 함께 포함해야 한다. 개정 자료를 저장만 해서는
답변이 바뀌지 않는다. 미래 시행일이나 과거 날짜의 적용을 자동 추정하지 않는다.
PDF·엑셀의 원래 레이아웃 편집 기능은 아니다. 새 원본과 편집 본문은 별도로 보존한다.

등록 자료
기존 36건에 누락된 검증 공개 근거 50건을 추가해 86건을 복원한다.
법령·지침 발췌 80건과 e-사람 매뉴얼 PDF 6개·총 221쪽이다.
공식 참조 목록과 원문 해시로 확인한 공개 자산만 추가했고 개인 업무 DB,
프로젝트·대화·기관 개정 기록, PC 설정, 모델 가중치는 동봉하지 않았다.
별도의 인사혁신처 제도 안내·FAQ 및 정형 답변 자료도 보존한다.
자료 보존과 원문 해시 일치 검증이며, 모든 법령의 현행성을 새로 조사하거나
여비 계산의 확인 기간을 갱신한 작업은 아니다. 저장본의 수집일·시행일을 확인한다.

새 설치 환경과 검사
같은 Windows 개발 PC의 한글·공백이 있는 새 경로에 후보 ZIP을 풀고 새 venv로
설치했다. install.bat에서 --no-index로 동봉 wheel만 사용했고 pip check가 통과했다.
run.bat과 같은 실행기를 --port 8897 --no-browser로 구동해 개인용 B 화면과
offline 기본 설정을 확인했다. 다른 물리 PC에서 실행한 결과는 아니다.

설치본 최종 검사:
- 서비스 Python 892개 통과(142.580초).
- 루트 Python 19개, 루트 Node 31개, 서비스 Node 32개 통과.
- 설치본 검사 합계 974개. 아래 실제 API 시나리오 16항목은 별도 집계다.

초기 전체 검사에서 프로젝트 파일 목록과 완료 상태를 서로 다른 시점에 읽는
동시성 문제가 재현됐다. 프로젝트 상세 조회를 하나의 SQLite 읽기 스냅샷으로
묶었다. 파일 조회 사이에 작업 완료를 커밋하는 결정적 회귀 사례를 추가했으며,
프로젝트 집중 검사 30개와 위 설치본 전체 재검사가 통과했다.
최종 패키지 실행 코드·자산은 이 보완 후 검증한 설치본의 해시와 대조한다.

기관 자료 실제 API 검증 — 16항목 통과
1. 기본 offline 설정 및 86개 원문 자산의 현재 해시·매뉴얼 쪽수 확인.
2. 예제 v1 원본 TXT 등록 후 초안은 답변에 나타나지 않음.
3. 비교·적용 후 같은 질문에 '교육 시작 3일 전'을 AI 없이 답변.
4. v2 TXT로 새 초안 저장 후에도 기존 답변은 '3일 전' 유지.
5. 비교에 '3일 전 → 5일 전' 표시, 적용 후에만 '5일 전'으로 변경.
6. 오래된 revision 요청 409, 다른 기관의 자료 혼입 차단.
7. 각 버전의 원문 텍스트와 내려받은 원본 TXT 사본이 저장 내용·파일 해시와 일치.
8. 적용 해제 후 검색 제외, 삭제 후 일반 목록 제외·삭제 목록에서 조회 가능.
9. 삭제된 버전 원문도 접근 가능, 복원 후 비활성 및 두 버전·이력 보존.
10. 입력 예제 TXT 파일의 내용·해시 불변.
세부 검사는 fresh-institution.json의 checks 16개를 참조한다.

서버 재시작 후 문서 전체 JSON(두 버전·7개 이력·비활성 상태) 및 설정 해시가
동일했다. 이후 실제 B안 화면에서 '다시 적용 → 이 자료로 질문하기 → 질문 →
근거 2 확인 → v2 관리'를 사용했다. AI 미사용, '5일 전', v2의 2행 원문과
해시를 확인했다. 마지막에 적용 해제하여 합성 자료를 비활성으로 남겼다.
이 화면 검증의 재적용·해제를 포함한 최종 이력은 9개다.
삭제·복원의 최종 클릭은 API로 검증했으며 화면에서 삭제 확인창을 자동 처리한
결과로 간주하지 않는다. 해당 검증용 DB는 제출 ZIP에 포함하지 않는다.

AI 없는 기존 질문도 새 설치본에서 확인했다:
- 아픈 자녀의 병원 동행: 휴가 안내의 규정 근거 1개와 관련 매뉴얼 근거 3개.
- 국가기관 사무용품 예산 과목: 예산·회계 근거 1개.
- e-사람 출장정산 입력: 출장 매뉴얼 근거 3개.
이는 검색과 출처 연결 확인이다. 모든 적용 조건의 법적 판단을 자동 승인하지 않는다.

모델 관련 범위
이번 기능 시나리오는 AI를 끄고 실행했다. 실제 모델 호출은 0회이며 Gemma·Llama
두 모델의 실제 재시험 결과로 인용하지 않는다. 호환 서버 연결과 형식 오류 처리는
자동 검사에 포함되며 과거 실제 모델 검증은 별도 v71/v74 기록이다.
설치본 테스트 로그의 LLM 오류 문구는 모형 서버 실패 처리 검사에 포함된 예상 로그다.

재현 방법
처음읽기.txt의 합성 예제를 따르거나, 새로 복원한 검증 전용 설치본의 service에서
다음 명령을 실행한다. 이미 기관 자료가 있는 설치본에서는 검증기가 중단된다.
.venv\Scripts\python.exe tools\verify_institution_rules_submission.py --base http://127.0.0.1:8781 --output verification.json
해당 검증기는 합성 자료를 만들고 마지막에는 비활성으로 둔다. 실제 사용 DB에서
테스트하지 말고 별도의 새 검증 설치본에서만 실행한다.
