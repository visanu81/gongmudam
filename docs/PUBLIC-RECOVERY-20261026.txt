공유 주소 연결 복구 — 2026-10-26

주소: https://gongmudam.visanu81.workers.dev/

확인한 장애
정적 B안 바탕화면은 200이었지만 /api/gongmudam/status, /api/ask, /calendar.html, /folders.html은 503 origin_unavailable이었다.
실제 브라우저에서도 ‘서버 연결을 확인할 수 없습니다’, 업무 목록 불러오기 실패가 재현됐다.
로그인 자동실행 기록 18:48:58의 prepare.log에서 Existing runtime differs 오류를 확인했다.

원인과 수정
prepare_public_runtime.py가 기존 공개 실행본의 설치 확인 값을 최신 개발본 매니페스트와 비교해 시작을 차단했다.
공개 실행본은 v74, 개발본 매니페스트는 v79였다. 공개 실행본의 관리 파일은 자체 매니페스트와 모두 일치했다.
기존 실행본은 자기 매니페스트·설치 확인 값·파일 해시·공개 시연 격리 표시·업데이트 잠금 상태를 검증해 재사용하도록 고쳤다.
새 개발본이 생긴 것은 업데이트 가능 상태로만 보고하고, 정상 기존 서버의 시작을 막지 않는다.
변조·누락·경로 이탈·개인용 환경·업데이트 중인 실행본은 계속 거부한다. 공개 DB와 설정을 덮어쓰거나 최신 개발 자료를 복사하지 않는다.

복구
기존 실행기 launch_gongmudam.py --headless --no-browser로 공개용 8892 서버와 기존 Cloudflare 터널을 시작했다.
같은 Workers 주소를 유지했다. 개인용 8787 서버를 공개하지 않았다.
회귀 검사: 실행본 준비 5개, 업그레이드 5개, 실행기 9개 통과.
검색·상태·달력·자료 정리·자료 취합 목록·출장 목록·도구함을 포함한 10개 HTTP 경로 모두 200으로 복구됨.
실제 공개 B안 화면에서 ‘국가공무원 병가에 진단서는 언제 필요한가요?’의 AI 미사용 답변·근거 표시와 달력의 기존 합성 교육 일정을 확인했다.
실행기를 다시 실행했을 때 server_started=false, tunnel_started=false로 기존 프로세스를 재사용했다. Windows 시작프로그램의 공무담 자동실행 바로가기도 남아 있다. 물리적 재부팅은 수행하지 않았다.
단순 연결 복구와 답변 품질·버전 동기화는 별도다.

남은 차이
공개 사이트는 보존된 v74 시연본이다. 이번 로컬 물품 근거 보강과 최근 v75 이후 변경은 자동 반영되지 않았다.
공개 화면에서 ‘본인이 아프면’ 질문은 관련성이 낮은 기존 안내를 반환했다. 연결 실패는 해결했으나 최신 자연어 답변 개선은 안전한 공개용 갱신 작업이 필요하다.
개인 업무 DB를 공개본으로 복사하는 방식으로 해결해서는 안 된다.

검증 도구
.local-verification/check_public.py: 공개 주소 상태·검색·달력·자료 정리 요청 검사.
urllib 기본 클라이언트는 이 사이트에서 403/1010으로 거절되어, 실제 앱 실행기와 같은 httpx 및 브라우저로 장애를 확인했다.
tests/test_prepare_public_runtime.py: 개발본 버전 변경 후 기존 공개 앱 보존, 자체 해시 검사, 변조/격리/잠금/경로 이탈 차단.
Graphify의 기존 서비스 지도는 루트 실행기를 포함하지 않으므로 tools/integration/tests/cloudflare 코드만 담은 별도 지도를 만들었다. 실행기·prepare·관련 회귀 테스트 연결을 확인했다. 실제 업무 DB·설정·비밀키는 지도에 넣지 않았다.
