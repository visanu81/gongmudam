공무담 실제 앱 — 기관 서식 연결·종류 표시·관리 재진입 수정
확인일: 2026-10-26

실행 앱: http://127.0.0.1:8787/desktop/?variant=B&v=77

1. 관련 서식 자동 연결
기존 안내는 과거 서식 저장소만 조회해 새 기관 자료 관리의 '서식'이 누락됐다.
질문 또는 답변에 인용된 원문에 등록한 서식명·연결어가 있으면, 같은 기관의
현재 적용된 서식을 '관련 서식'에 연결한다. 기관명·기준일·현행 포인터·활성
상태를 검사한다. 다른 기관, 미적용 초안, 비활성·삭제 자료, 기준일에 맞지 않는
자료는 연결하지 않는다. 관계 추론이나 AI가 서식을 필수 제출물로 자동 판정한
결과가 아니라 등록 자료의 이름·연결어가 일치하는 서식 후보를 제공하는 기능이다.

서식 이름에 종류와 버전을 표시하고 현재 적용본의 보존 원문을 새 탭으로 연다.
옆의 '관리' 링크는 같은 버전의 관리 화면으로 이동한다. 로컬 경로와 UUID를
검사하며 임의의 외부 주소를 서식·관리 링크로 사용하지 않는다.

2. 서식 종류 표시
기관 자료를 검색 자료로 옮길 때 종류를 모두 '기관 지침'으로 변환하던 코드를
수정해 실제 등록 종류를 유지한다. 기존 등록 자료도 불변 버전의 종류를 읽어
표시하므로 재등록할 필요가 없다. 옛 원문·버전을 덮어쓰지 않는다.

3. 동일 관리 링크 재진입
대화창이 iframe 내부에서 이동한 뒤 부모 창의 마지막 주소가 남아 있으면 같은
관리 링크가 무시됐다. 신뢰된 자식 창에서 명시적으로 요청한 이동은 목적 주소가
같아도 실행한다. 일반 바탕화면 아이콘의 창 재사용·초점 동작은 유지한다.

검증
두 API 실패와 반복 이동 실패를 먼저 재현한 뒤 수정했다.
기관 관리 집중 검사에는 연결된 서식 원문·버전, 기존 변환 자료의 종류 복구,
기관·날짜·초안·활성/삭제/복원 상태, 새 초안 적용 전후의 링크를 포함한다.
화면 검사에는 안전한 원문 주소, 종류·버전 표시, 관리 주소의 UUID 보존과
일반 창 재사용/명시적 반복 이동을 포함한다.
전체 실행 결과는 docs/evidence/institution-form-fixes-20261026/의 로그에 보관했다.
최종 서비스 Python 897개(197.121초), 루트 Python 33개, 루트 Node 39개,
서비스 Node 33개가 모두 통과했다. 합계 1,002개이며 집중 검사 54개는 별도 합산하지 않는다.
초기 전체 실행에서 새 API 검사가 다른 검사의 임시 설정 경로에 의존하는 오류가
발견됐다. 해당 검사에 독립적인 offline 프로필을 고정한 뒤 위 전체 검사를 다시 통과했다.
Graphify 관리 지도도 갱신했다(197파일·3,350노드·9,837연결, 모델 토큰 0).

실제 사용하는 앱에서 합성 시연 자료 두 건을 잠시 재적용했다.
- 지침을 지정한 질문에도 '관련 서식'에 제출서 · 서식 · v2가 나타났다.
- 해당 링크를 눌러 새 탭의 원문이 연락처를 포함한 v2인지 확인했다.
- 서식을 질문한 답변의 근거 종류가 '서식'으로 표시됐다.
- 관리 → 대화 → 같은 v2 관리 링크를 두 차례 반복해 모두 관리 화면으로 돌아왔다.
- 서식을 적용 해제한 뒤 같은 지침 질문에서 관련 서식이 빠지는 것을 확인했다.
- 마지막에 합성 지침도 적용 해제했다. 두 자료는 비활성이고 각 2개 버전·이력을 보존한다.

AI를 끈 상태로 확인했으며 실제 모델 호출은 0회다.
기존 프로젝트 5개·파일 12개·대화 46개 및 자료함·원문 색인·불변 규정 버전과
모델 설정이 그대로 유지됐음을 사전 백업과 대조했다.
백업은 .local-verification의 개인용 자료이며 배포 자료가 아니다.
