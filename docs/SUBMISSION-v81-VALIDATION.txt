이번 릴리스 반영 내용
Upstage Solar Pro4 프로필을 기본 활성으로 제공한다. API 키는 배포본에 포함하지 않으며,
사용자가 B안 업무 설정의 AI 모델 설정에서 연결 주소·모델명·고급 설정 비밀번호를 입력하고
연결값 저장 및 실제 응답 확인을 진행한다.
연결 주소는 https://api.upstage.ai/v1, 모델은 solar-pro4, 추론 설정은 none이다.
키는 서버 설정에만 저장하고 채팅이나 배포 파일에 포함하지 않는다.
프로젝트 질문과 검색 발췌문은 Upstage로 전송된다. offline 프로필은 프로젝트·채팅을 포함한 모든 AI를 끈다.
AI가 허용된 경우에도 채팅의 AI 사용 체크를 끄면 채팅은 AI를 사용하지 않는다.
별도 설치형 Ollama에서 local_gemma(gemma3:4b), local_llama(llama3.2:3b)를 연결할 수 있다.
Ollama 주소는 http://127.0.0.1:11434/v1이며 각 모델 가중치는 별도 설치가 필요하다.
기존 v80 안내와 service/sample_data/notebook-v80 예제, 검토된 공통 자료 123건을 유지한다.
개인 DB·소속·프로젝트·대화·기관 비공개 원문·사용 설정·API 키는 배포하지 않는다.

기존 연결에 대한 확인 기록
기존 개인용·공유 시연 환경에서 Upstage 실제 응답을 solar-pro4-260806 모델로 확인했다.
동일한 여비 질문과 인용문을 AI 켬/끔 양쪽에서 확인했다.
합성 프로젝트의 미회신 부서 회계과와 회신 마감 2026-11-06을 기록한 확인은 완료했다.
해당 기록은 기존 연결과 데이터의 결과이며, v81 새 설치에서의 확인으로 간주하지 않는다.
기존 자동검사 105개 통과 기록을 확인했다. 이번 변경 전체를 새 설치에서 재실행한 수치는 아니다.

v81 새 설치 검증 — 완료 (같은 Windows PC의 별도 폴더)
새 venv를 만들고 동봉 wheel에서 --no-index 설치, pip check 통과. 공통 자료 123건 복원.
기본 upstage / 키 없음 상태를 확인하고 실제 질문이 AI 없는 원문 검색으로 응답함을 확인했다.
새 설치본 설정 API로 키를 저장하고 키가 조회 응답에 노출되지 않음을 확인했다.
실제 응답 시험 verified와 solar-pro4 계열 응답을 확인했다. 출장 질문에서 source_llm으로 근거를 선택했다.
키 없는 답변과 업스테이지 사용 답변의 원문 인용은 일치했다.
local_gemma → local_llama → offline 전환과 저장을 확인했다.
새 설치본 업스테이지 검사 7개와 제출 모델 설정 검사 5개 통과.
offline에서 합성 폴더·파일 3개 추가, 미회신·요약·일정·비교·초안·근거 부족 질문 6개 검증.
모든 인용의 원문 위치 및 원본 해시 일치, 초안 저장, 재조회 보존, 원본 불변을 확인했다.
실제 다른 물리 PC에서 수행한 검사는 아니다. Gemma·Llama의 실제 생성 응답은 이번에 재시험하지 않았다.
서버 종료·재시작 비교는 이번 검사에 포함하지 않았다. 법령 현행성이나 계산 기간을 갱신하지 않았다.
